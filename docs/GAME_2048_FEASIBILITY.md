# 2048 — candidate game feasibility and read-only prototype

**Status (2026-10-20 EDT / 2026-10-21 UTC):** Candidate **researched**, manual observation-and-move **preview implemented**. Game control, automated inputs, screen reading, streaming rights, and public broadcasting are **not authorized or tested**.

## Why 2048 first

Gabriele Cirulli's original 2048 is a compact, deterministic *four-direction slide-and-merge* browser puzzle. The upstream repository publishes its code under the MIT license and explicitly mentions arrow keys and mobile swipe support. A browser can potentially present the game on Android and Xbox Edge, though neither device has been tested for this integration. The official source is available with no Clanker-specific player account setup; it is not a live online-service game. A 4×4 integer grid is easier to review than video-game screenshots, and there is no need to interact with Twitch, third-party accounts, or a controller yet.

Primary references checked:
- Author's source/readme: https://github.com/gabrielecirulli/2048
- Author's MIT software license: https://github.com/gabrielecirulli/2048/blob/master/LICENSE.txt
- Author's game HTML/rules: https://github.com/gabrielecirulli/2048/blob/master/index.html
- Author's original-host site: https://gabrielecirulli.github.io/2048/

**Rights boundaries:** MIT grants permissions regarding licensed **source software** subject to preserving required attribution/licensing when distributing copies. This is not a verified blanket authorization for automation against every online 2048 host, for all artwork/brands, or for commercial livestreaming. No external hosted website was programmatically controlled. No external game source or artwork was imported into Clanker's public repo. Clanker's analyzer is newly implemented, game-neutral branded UI plus original 2048-style rules logic.

## Implemented board-study contract

```json
{
  "schema": "clanker.2048.board.v1",
  "board": [
    [2, 2, 4, 4],
    [0, 2, 4, 8],
    [0, 0, 8, 16],
    [0, 0, 0, 0]
  ]
}
```

- Exact required keys `schema` and `board`; **reject** all other fields, including `origin`, permissions, commands, or injected metadata.
- Exactly four rows of four tiles; values are `0` or power-of-two integers `2..131072`. UI input max 1,400 characters.
- Runtime labels all manual input `manual_lab`. It is never automatically collected, authenticated, network-fetched, or injected into a game.
- Analyze legal `left`, `down`, `up`, `right` slide results; merge equal neighbors once per tile; compute immediate merge points and empty squares. No random tile is generated. Display candidate slide and hypothetical post-slide board; never apply it to an external or internal playable game.
- Transparent deterministic one-step heuristic: `24 * empty_cells + merge_points / 4 + 14 if max tile sits in corner`. Tie order is left, down, up, right. Crew may influence a *legal near-tie* within 12 points but cannot force an illegal/substantially lower-ranked move.
- Blocked board yields `candidate:null`. Output always includes `execution:NONE`, `authorization:NOT AUTHORIZED FOR REAL GAME CONTROL`. No key events, WebSocket/game POSTs, background tasks, Twitch postings, LLM requests, or speech are generated by this lab.
- The manual preview is intentionally not a competent 2048 player: no tile-spawn uncertainty, multi-ply search, calibrated win rate, hidden UI state, game-over observation transport, or persistence. Do not present its proposals as autonomous gameplay.

## Feasibility and future engineering gates

**Access / price:** Existing browser-only JavaScript, no paid endpoints or new accounts for the preview. Do not add CI or recurring automation merely to support the lab.

**Observation:** On the official third-party site, Clanker's separate browser origin cannot read its live DOM by ordinary same-origin web APIs. Future same-origin approved self-hosted gameplay may offer direct board state access, but would involve additional game licensing/attribution, privacy, delivery, and permission reviews. Screenshot-based recognition on Xbox/Android has not been established and must not be assumed.

**Actuation:** The only documented original game controls are arrows/mobile swipes; *no controls are wired here*. Any in-page game actuator would need owner authorization for **this specific game/mode**, a publisher/source/host policy check, an opt-in pause/stop, action rate limiting, verifiable observation freshness, fail-closed behavior, recovery, and separation of Twitch advisory input. Even an MIT-licensed self-hosted copy must not silently become a public autonomous stream.

**Entertainment:** The puzzle provides transparent strategy and teachable failures, but may be repetitive over long streams. Add personality commentary only after observation-based facts are reliable; do not claim game mastery, independent play, or actual wins based on scripted predictions.

**Acceptance now:** Correct bounded manual board validation; deterministic merge-once slides; legal/blocked/unknown input handling; clear provenance and no execution; compatibility with current v2.5 portrait, queues, privacy and memory. A physical Android/Xbox smoke check and genuine Node CLI remain unverified.

**Next safe step:** Improve manual observations with explicit game-over and input-quality explanations, explore non-operational multi-ply candidate evaluation, and seek one actual Node/browser regression run via a permitted free byte-transfer path. **Next hard gate:** name/approve `2048 — original MIT licensed, private same-origin browser instance, no public broadcast` as the specific target and approve scoped control *after* rights/terms and host review; no generic "proceed" is substituted for that authorization.

## First local gameplay implementation — owner approved 2026-10-20 EDT (2026-10-21 UTC)

The owner explicitly authorized moving into the previously discussed 2048 game. This milestone implements a **standalone in-page playable puzzle**, not remote control or automation of the upstream game URL. It needs no third-party host credentials or page cross-origin access. The Clanker repository and GitHub Pages source are public; the actual running session and its ephemeral board remain in the user's own browser. Do not describe this as a private *deployment* of the original game's repository.

**Upstream rights check:** Gabriele Cirulli's official [2048 repository](https://github.com/gabrielecirulli/2048) declares MIT; [LICENSE.txt](https://github.com/gabrielecirulli/2048/blob/master/LICENSE.txt) states permission to use and modify its software subject to preservation of notice in copies. Clanker's new in-page rules/visual interface are independently implemented and copy no original upstream source files, images or proprietary game assets; attribution to the original concept is embedded in the page and docs. No third-party host is driven or bypassed. Public streaming and monetization are not authorized.

**Actual runtime:** Press New to initialize exactly two random 2/4 tiles, manual direction buttons for owner moves, single Clanker move, or separately opt in to timed autonomous play. Game-local 4×4 state includes score/turn count and win/loss flag. Successful legal moves merge tiles according to 2048 slide rules and spawn one new tile (90% 2, 10% 4). Illegal moves do nothing; blocked boards stop; 2048 tile ends in win. Two-ply chance-aware finite heuristic considers all spawn positions and 2/4 probabilities for the reply move, with empty-cell, corner, merge and smoothness terms. It is **not trained learning**. Owner-entered directional advice is only considered inside a 15-point quality margin.

**Actuation confinement:** The only executor is `moveLocal2048()`, which mutates the app-created `local2048.board` variable; this is a real playable puzzle turn, distinct from `runAdapter()` (scripted encounter) and the 2048 read-only study `study2048()`. No cross-origin DOM access, keyboard synthesis, controller events, OS automation, HTTP/WebSocket/game-server calls, Twitch command execution or new permissions. No LLM/Gemini dependency; no new persistent storage keys.

**Safety:** Autoplay starts only on owner button click; 1500 ms between steps, 128 steps maximum per start, one timer, STOP button, page visibility stop, new game stop, terminal win/loss stop. Owner can play manually only while timer is stopped; Clanker runs at most one deterministic decision per timer tick. Tab refresh clears the ephemeral board and stops autoplay by destroying its timer. There is no background gameplay, paid resource, CI schedule or persistent agent.

**Verification:** Offline regression script expanded to cover actual random-tile initialization, legal first autonomous turn, four manual controls, start/stop, no late ticks, hidden tab fail-closed, reset, capped autoplay or natural game end, no network and untouched existing memory backup; existing Twitch EventSub, privacy, nine faces, avatar and read-only lab checks also preserved. Actual test-run environment and exclusions are documented in the canonical handoff.

**External-game gate not satisfied:** Connecting Clanker to an existing hosted 2048 website, another publisher's game, device inputs, a persistent broadcasting service, or real paid/public distribution would require distinct policy, hosting, privacy, device, attribution and owner approval. Local self-contained gameplay demonstrates mechanics and independent choices but does **not** establish external-game competency, service-bot approval or game screen recognition.

## Gameplay telemetry and reviewable history — 2026-10-21

The playable self-contained game now retains a bounded, **ephemeral** `local2048History` array of at most 513 frames (the initial board plus recent successful turns). A frame contains a clone of the actual after-move board, turn index, score, status, player source (`Clanker` or `Owner`), move direction, merge points, precisely returned random spawn coordinates/value, highest tile and number of empty squares. On overflow the earliest frame is dropped and `completeFromStart:false` is set in any subsequent export. Frames are rendered separately in **Review actual moves**, never injected back into the game state. The replay is review-only, not deterministic re-simulation or restoration.

The user can explicitly download `clanker.local2048.evidence.v1` JSON; there is no automatic upload, storage key, viewer identity, API key or account authorization in it. Exports are session-derived local-game evidence, **not** cryptographically signed evidence of external gameplay or third-party Twitch delivery. New local game and reload wipe the history. There is no background session replay, network service, or extra recurring cost.

**Character behavior:** Local board milestones (new high tile at or above 64, scarce empty cells, unusually large merge, actual win/loss or every 16 turns) choose small original Clanker lines using the just-executed game's measurements. The UI reports commentary for moves. Spoken output is separately opted into and also depends on browser Voice on; routine turns are not spoken. It defers speech when other voice activity or model/live-chat responses are active. The avatar's existing mood expression is driven by these specific moments without replacing any portrait assets. This is rules-based game-aware commentary, not a model learning gameplay.

**Crew boundary:** Offline chat about gameplay acknowledges current local board score and highest tile if a game is active, avoiding outdated claims that no game is available. This is only dialogue; neither live nor offline viewer text directly invokes `moveLocal2048`. In-game advice remains a bounded owner-selected dropdown and cannot grant new authority.

**Verification:** The existing dependency-free regression script was extended with genuine board-history/replay checks, export schema and redaction checks, reset, active-game chat truthfulness, and opt-in voice defaults. Full execution was **43 PASS** in the connected JavaScript V8 isolate with Node/DOM shims; source parsing, existing Twitch mocks/privacy tests and built-in 28/28 passed. This still does not establish a real Node CLI run, a physical browser voice test, or gameplay skill against the original third-party game host.

## Seeded strategy comparison — 2026-10-21

After user-authorized continuation, Clanker's local 2048 two-step policy received a bounded positioning heuristic: eight corner-origin snake paths with decreasing weights, to favor orderly storage of larger tiles. No external-game control, real screen observation, Gemini usage, network calls, account permission or Twitch command capability was added. In **48 offline paired-seed comparisons**, the current strategy outperformed the old one by about 3.8% mean score in both development and holdout groups over 128 turns. Nobody reached tile 2048. See [`2048_BENCHMARK.md`](2048_BENCHMARK.md) and reproducible `node tests/benchmark2048.cjs`; all results are synthetic, not observed physical browser gameplay and not evidence of learning. This is a conservative heuristic update selected after comparing candidates, not a guarantee of competence.
