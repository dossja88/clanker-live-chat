# Clanker: public stage versus private development — preparation checkpoint

**2026-10-25 UTC. Status: LOCAL PACKAGING TOOL ONLY, NOT DEPLOYED.** Owner wants the source repository private without breaking current browser Brain Lab and stage. This work prepares the existing, already-public **read-only stage** as a narrow candidate. It **does not** change GitHub visibility, Pages, the Twitch application, account permissions, public hosting, Cloud services or the active game state.

## Verified current deployment coupling

- `dossja88/clanker-live-chat` is **public** on `main`; project Pages has historically served [the Brain Lab](https://dossja88.github.io/clanker-live-chat/) and [the clean stage](https://dossja88.github.io/clanker-live-chat/stage.html). This live site was not re-tested on a device or by a live authenticated Pages configuration query in this checkpoint.
- `index.html` includes in-browser simulated/offline game logic, opt-in Twitch/EventSub and opt-in Gemini paths; its browser-shipped JavaScript is inspectable **even when the source repository is later made private**. Putting the same complete app in a public Pages repository would not hide that client code.
- `stage.html` is a **66,249-character, single-script standalone HTML** read-only receiver. Authenticated source SHA-1 blob: `5323bdce4c4fc122c422e66b5763442683805fee`. It does not call `fetch`, `WebSocket`, local/session storage or credential forms in its current source (bounded static scanner, not a full security review). It sends exactly one **type of message**: a `clanker.stage.request.v1` snapshot request to `BroadcastChannel('clanker.stage.v1')`, and receives local sanitized board/status state. The source Brain Lab needs to stay active. This is **not** an Internet streaming backend, access control or authenticated message transport.
- The channel is **same-origin** (scheme + host + port), not same-repository/same-path. Moving only `stage.html` to another **path on `https://dossja88.github.io`** could retain access to a separately active Brain Lab on that same origin; moving the source Brain Lab to a private repository with no active public served page would **stop stage updates**. Other hostnames/origins cannot transparently use this channel.
- The existing separate public `dossja88.github.io` user-site repository contains only small `index.html`, `privacy.html`, `terms.html`, `style.css`, a verification file and `.nojekyll` as of inspection. This audit did not change or test that Pages deployment. Changing its files, using a colliding `clanker-live-chat/` path, or transferring projects is a **distinct public deployment** that needs review and approval.

## New reproducible local-only packaging and safety checks

- [`scripts/package-public-stage.cjs`](../scripts/package-public-stage.cjs) imports only `stage.html`, applies a restrictive rule set to reject newly added fetch/websocket/storage/service-worker/password/external-asset/dynamic-code functionality, and checks the stage channel contract; it creates a **new owner-private OS temp directory** with an exact HTML copy named `index.html` and a SHA-256/byte-count `manifest.json`. It does **not** package `index.html`, the private headless core, tests, docs, credentials or entire repository.
- Its manifest explicitly says `LOCAL_CANDIDATE_NOT_PUBLISHED`, `ownerPublicReleaseApproved=false`, `networkBackend=false`, `requiresActiveSameOriginBrainLab=true`, `retainsFullBrainLabFunctionality=false`. It is a **candidate**, not a public website, secure proof, finished art acceptance, or permission to deploy.
- [`tests/package-public-stage.cjs`](../tests/package-public-stage.cjs) checks the actual stage source, byte-exact temporary package, private-release flag and eight hostile mutations (network fetch, password input, local storage, external image, extra channel send, missing receive, wrong channel and extra script). **The real GitHub stage HTML passed a corresponding in-tool structural check and all eight injected mutations were rejected.** A local Node v22 syntax + packaging test passed on a **synthetic stage fixture**, NOT a full clone of the actual GitHub source. Do not claim the checked-in Node test ran against the real `stage.html` in an authenticated repository checkout. No current Clanker `tests/regression.cjs` suite or cross-device/Pages test was run or claimed for this docs-and-additive-tool change.
- Safety boundaries: a negative-pattern static audit is NOT a complete JavaScript security audit, runtime/browser QA, source privacy assurance, or proof of absence of malicious content. A same-origin `BroadcastChannel` is not an authenticated remote channel. Review the exact candidate before intentional public release.

## Migration choices; no premature visibility change

1. **Current (safe):** Keep public Pages/Brain Lab functioning; keep repository public and approved assets intact; use this exporter for an isolated local candidate only. Continue building headless game/state/security code without importing private tokens or viewer data into public Git.
2. **Possible later:** With explicit approval and live device/Pages checks, put **only separately reviewed public client files** at a conflict-free path on an existing compatible public static host, retain same-origin tab contract only while the Brain Lab itself still runs on that origin. Source repository can become private only after every required public dependency is actually migrated and tests confirmed, and Jules/GitHub App permissions re-verified.
3. **Long-term:** Private headless Clanker runtime and memory; separately hosted minimal public stage driven by a **new authenticated, privacy-filtered, read-only output relay**. This relay does not exist; requires its own design, cost/free-resource proof, credentials/hosting/security reviews and authorization. Do not silently start cloud hosting or add credentials.
4. **Privacy limit:** Publicly distributed browser HTML/JS and image/voice assets are still visible and copyable. A private GitHub repo only hides files **not distributed to the client**. Credential inputs on a public page are not themselves embedded public secrets; nevertheless browser clients/third parties require careful privacy review. Never put persistent secret tokens, client private data or private memory into public assets.

**Future release acceptance:** Owner approves the exact public candidate/path and expected exposure; no existing route collision, no new unvetted assets; independent source-to-built hash; public stage and source Brain Lab behavior verified in real intended browsers on the same origin; no credential/network-storage exposure; no changes to STOP/replay/forget protections; archive/recovery path tested; private headless work and Jules PR remains accessible under chosen permissions. Then—and only then—make the repository private if the remaining Pages host and account plan support required functionality. If any step fails, keep current Pages public and preserve working project state.

**Cost and scope:** Added recurring charges $0; no new hosting, subscriptions, OAuth scopes, external account, public release, CI runner, code merge, repository visibility change, source-media migration or credentials touched. Draft PR #11 remains separate Jules-owned work and was not merged or changed.
