## Security, privacy, economics and external gates

- Keep existing public repository visibility and GitHub Pages boundaries; never commit passwords, OAuth codes/secrets/tokens, private Twitch messages, customer data, private memory, broadcaster credentials, PII, account recovery, or unpublished private assets. Respect `forget`, queue cancellation and privacy/schema invariants and do not publish viewer content into Git. Do not create/expand Twitch/OAuth scopes or third-party permissions without owner security approval. Browsers cannot silently inherit a host identity.
- **Billing disabled; $0 added recurring costs**, no upgrades/trials/metered calls without explicit cost and owner approval. Distinguish a local engine checkpoint from durable storage, security against rollback, private hosting, network authenticity, uptime or actual Twitch game actuation. Do not publish new channels, push a live broadcast, run bot against real games, add external account or deploy a cloud host without relevant separate owner approval.
- Creator account/Drive is **conditional**, not standing Clanker write permission. If specifically approved, use dedicated creator Google account/project-owned Restricted folder; never personal Drive, shared links, unauthorized uploads or automatic deletes. User-evaluated temporary previews are cleanup candidates **only after actual evaluation and preserved recovery path**, and require exact per-file owner deletion approval.
- Durable media, licensing, commercial/release compliance and original character identity apply to portraits, voices, gameplay streams and clips; technical tests/preview do **not** authorize a public broadcast or actual third-party game actions.

## Engineering and test contract

- Start with `node tests/regression.cjs` for changed browser/behavior code and `node scripts/run-offline-tests.cjs` for full relevant offline suites; require full final PASS summary **and exit 0** from actual Node when claiming test success. Simulated Twitch/EventSub, OAuth, visual browser, local game engine, headless games and live Twitch are different evidence levels. Do not claim browser/Xbox/live-host tests from connector JavaScript shims. No persistent CI runner or secret-bearing workflow by default.
- For checkpoint/receiver work, preserve versioned fenced epochs, STOP floors, immutable data, strictly validated bounded input, atomic failure and owner authorization. The verified `exportCheckpoint`/`restoreCheckpoint` controls in `src/stage-reconnect.cjs` are offline primitives; they do not provide secure atomic on-disk persistence or remote operator authentication. For eventual local durable cursor/CAS bridge, require crash/rollback/symlink/stale-writer/restart and recovery tests before any network transport.
- Keep protected source, tested branch and source-blob identity, preserve all current public pages/robot assets unless specific scope. Verify only changed behavior, code + tests and final Git remote commit. If actual tool/runtime unavailable, report honestly, no fictional deployment.
